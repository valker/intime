## Цель

Обеспечить запуск подходящих тестов агентом при работе над проектом: локальные
JUnit/Robolectric и инструментальные проверки на выделенном Android-эмуляторе.
Каждый запуск должен завершаться понятным результатом, логами и свежими отчётами.

## Проверенное исходное состояние

- Установлен JDK 17.0.10; Java доступна через PATH, JAVA_HOME не задан.
- Gradle Wrapper: 8.10.2; Android Gradle Plugin: 8.8.2.
- Android SDK находится по пути из local.properties; установлены platform 35
  и build-tools 35.0.0.
- adb доступен; подключённых устройств на момент проверки нет.
- Установлен современный emulator/emulator.exe, есть AVD Pixel_8.
  Команда emulator из PATH указывает на tools/emulator.exe: запускать современный
  бинарник по разрешённому пути SDK.
- В src/test есть JUnit и Robolectric; старые XML-отчёты от 11 июля 2026 года
  содержат 30 тестов без ошибок. Это не подтверждает текущую версию.
- В src/androidTest есть четыре теста миграции Room 5 → 6.
- Предыдущий запуск остановлен при подготовке графа задач Gradle. Причина неизвестна.
- CI устанавливает SDK 34, тогда как приложение использует compileSdk 35.

## 1. Диагностика и стабилизация Gradle

- Повторить запуск с --console=plain --info --stacktrace и логом в проекте.
- Сравнить работу с включённым и отключённым configuration cache; отдельно
  проверить запуск без переиспользования daemon. Менять настройки по результатам.
- Проверить блокировки, доступ к кешам, запуск дочерних процессов и доступность
  зависимостей. Не считать sandbox или сеть причиной без конкретной ошибки.
- Проверить Maven-зависимости Robolectric: offline Gradle сам по себе не
  гарантирует отсутствие загрузок во время выполнения Robolectric.
- Предусмотреть первичное получение зависимостей и повторный автономный запуск
  из подготовленного кеша. Для внешних каталогов применять разрешённый способ
  доступа; при необходимости использовать отдельный кеш в проекте.
- Зафиксировать JDK 17 и UTF-8; размер heap выбирать по фактическим потребностям.

Готовность: свежий полный запуск :app:testDebugUnitTest завершается и создаёт
XML/HTML-отчёты; повторный запуск с --rerun-tasks также успешен.

## 2. Единая команда локальных тестов

- Добавить scripts/test.ps1 с режимом local и фильтром класса/метода.
- Выполнять предварительную проверку JDK, SDK и Gradle Wrapper.
- Запускать :app:testDebugUnitTest; сохранять stdout/stderr, код завершения,
  длительность и сводку XML-результатов в игнорируемый каталог проекта.
- Ограничить время запуска; при превышении завершать только принадлежащие
  запуску процессы. Не завершать чужие сборки и не очищать общие кеши.
- Различать FAILED, PASSED, UP-TO-DATE и ошибку инфраструктуры; исключить
  выдачу старых отчётов за результат текущего запуска.

Готовность: одна команда запускает всю локальную suite или выбранный тест;
  ненулевой код и отсутствие свежих результатов не маскируются успехом.

## 5. Правила работы агента и CI

- Добавить TESTING.md с командами, требованиями, диагностикой и путями отчётов.
- Добавить AGENTS.md с разрешением запускать локальные и инструментальные

- Указать: расчёты/импорт/DAO — локальные проверки; миграции — дополнительно
  инструментальные; Android lifecycle/уведомления — соответствующие доступные
  проверки. Инфраструктурные ошибки сообщать отдельно от ошибок приложения.
- Согласовать CI с SDK 35 и локальными командами; публиковать JUnit и логи
  при успехе и ошибке. Инструментальный CI требует runner с доступным ускорением;

- Проверить негативные сценарии запуска: неверный SDK, отсутствие устройства,
  timeout и падение теста.

## Итоговый критерий

Агент из терминала запускает local/device, получает свежие результаты и может
  повторить запуск без ручного открытия Android Studio. Первичная настройка и
  загрузка компонентов могут потребовать доступа за пределы sandbox; инструкция
  проекта не отменяет ограничения среды исполнения.
