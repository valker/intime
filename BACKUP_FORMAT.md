# Формат резервной копии и правила импорта

Обновлено 2 октября 2026 года, R3.1. Версия JSON-формата — **1**, версия Room-базы — 6.

Корень — один объект с `tables.tasks.rows`. `rows` — массив строк-массивов.
Каждая строка содержит ровно восемь значений в следующем порядке:

| Поле | Допустимое значение |
| --- | --- |
| `id` | Уникальное в файле целое от 1 до 9223372036854775806 |
| `description` | Строка, в том числе пустая; число, boolean и null не допускаются |
| `interval` | Целое 0–5: минуты, часы, дни, недели, месяцы, годы |
| `amount` | Целое от 1 до 2147483647 |
| `next_alarm` | Целое от 0 до 9223372036854775807, Unix-миллисекунды |
| `next_caution` | То же |
| `last_ack` | То же; 0 допустим |
| `quant` | Целое от 1 до 2147483647 |

Числовые значения не преобразуются из строк, дробей, boolean или null.
Запись `1.0` также отклоняется. Парсер использует существующий `org.json`;
отдельная строгая проверка синтаксиса по RFC не реализована.

`id = 0` отклоняется, поскольку Room назначил бы другой ID. `Long.MAX_VALUE`
отклоняется, поскольку его вставка немедленно исчерпала бы SQLite AUTOINCREMENT.
Повторяющиеся ID отклоняются даже при одинаковых строках: импорт не должен
незаметно терять задачи из-за стратегии REPLACE.

Текущий экспорт всегда содержит `meta.version = 1`, `meta.exportedAt` и
`tables.tasks.columns` с точными именами восьми полей в указанном порядке.
При импорте действуют следующие правила совместимости:

- Отсутствующая `meta` означает старый позиционный формат v1.
- Если `meta` присутствует, это объект с обязательной целой `version = 1`.
  Неизвестная версия, пустая meta, null и неверный тип отклоняются.
- `exportedAt` необязателен при импорте; если указан, это неотрицательное целое long.
- Отсутствующие `columns` допустимы. Если они указаны, имена, порядок и число
  колонок должны точно соответствовать таблице выше.
- Неизвестные дополнительные свойства корня, meta и таблиц игнорируются.
  Дополнительные поля внутри строки задачи и данные после корневого объекта отклоняются.
- `rows = []` — корректная полная очистка списка задач.

Импорт полностью заменяет список, сохраняя ID, но не переносит `wasNotified`:
для импортированных задач он начинается с false. Все строки проверяются до
удаления старых данных, затем замена выполняется в одной Room-транзакции.
При ошибке валидации задачи и установленный будильник сохраняются.

R3.1 проверяет представимость параметров и структуру файла. Безопасность
арифметики с крайними значениями, календарные границы и отношения временных
полей проверяются следующим шагом R3.2; допустимое число ещё не означает,
что любой дальнейший расчёт срока с ним безопасен.
