# Intime v2 — актуальный roadmap

Обновлено 2 октября 2026 года. Документ определяет текущие приоритеты и статус.
Реализованные функции и неподтверждённые релизные проверки перечислены отдельно.

## Подтверждённое состояние

- Рабочий MVP: список, добавление/редактирование, детали, ACK, удаление,
  настройки разрешений, локальный импорт/экспорт.
- Java/XML, ViewModel/LiveData, Room (схема 6), отдельный ReminderCalculator.
- AlarmManager планирует ближайшую задачу; WorkManager проверяет пропущенные
  уведомления; BootReceiver восстанавливает расписание.
- Старые UI/SQLite runtime-пути удалены. Развиваем только текущий стек.
- Короткое нажатие открывает детали; возврат на главный экран уже реализован.
- 2 октября прошёл 51 локальный тест и 5 инструментальных тестов на API 35.
  Автономный online/offline-запуск описан в TESTING.md.
- CI обновлён, но успешный GitLab pipeline не подтверждён.
- Production-обновление v1, smoke-матрица и подписанный релиз не подтверждены.
  Тесты миграции 5 → 6 используют искусственные данные.

## Порядок работы

Каждый пункт выполняем отдельным проверяемым шагом: исправление, регрессионные
тесты, подходящие проверки, обновление статуса. «Реализовано» и «проверено на
устройстве» отмечаем отдельно. Переход на Kotlin/Compose не является условием релиза.

### Шаг 1. Надёжность уведомлений — текущая работа

- [x] R1.1: исправить идентичность ACK PendingIntent, чтобы действие относилось
  к нужной задаче при последовательных уведомлениях.
- [x] R1.2: единообразно учитывать POST_NOTIFICATIONS, общий запрет уведомлений
  и отключённый канал; не ставить wasNotified при заблокированной отправке.
- [x] R1.3a: устаревшие и повторные будильники — читать актуальную задачу из Room;
  пропускать удалённые, перенесённые в будущее и уже уведомлённые задачи;
  использовать актуальное описание. Четыре новых регрессионных теста прошли.
- [x] R1.3b: одинаковые сроки, открытый UI, восстановление разрешения и конкуренция
  worker/receiver покрыты локальными тестами. Выборка, отправка и отметки идут
  в Room-транзакции; receiver отмечает все задачи из сводки, worker учитывает UI.
- [x] R1.4: worker повторяет сводку просроченных задач без звука, вибрации и ACK,
  открывая список задач. Минимальная пауза — 15 минут после успешной отправки;
  новые пропущенные задачи обрабатываются сразу. Время отправки хранится в настройках.
- [ ] R1.5: проверить доставку и ACK на API 33/35, включая отказ в разрешении,
  отключённый канал и перезагрузку; сохранить фактические результаты.

Готово, когда регрессии воспроизводятся тестами, исправления проходят локальную
suite, а поведение разрешений/доставки подтверждено инструментально или вручную.

R1.1/R1.2 реализованы: URI с ID задачи для ACK, единая проверка отправки для
alarm/worker/boot. 2 октября прошли все 39 локальных тестов, включая 9 новых
регрессионных сценариев, и 5 инструментальных тестов на API 35. Новый device-тест
отправляет ACK через настоящий PendingIntent и подтверждает только вторую задачу.
Доставка уведомлений и reboot остаются в R1.5; очереди фоновых операций — в шаге 2.

R1.3a реализован; 2 октября прошла полная локальная suite: 43 теста, без ошибок.
Повторный device-прогон на API 35 также прошёл: 5 тестов (миграции и ACK).
Отчёты: `.test-tools/runs/20261002-111910-ffcb688b/summary.json` (local) и
`.test-tools/runs/20261002-112020-9831c4a4/summary.json` (device).
Проверяется устаревший Intent после удаления и ACK, повторная доставка и изменение
описания.

R1.3b реализован; полная локальная suite прошла: 46 тестов. Добавлены проверки
двух задач с одинаковым сроком, подавления отправки обоими обработчиками при
открытом UI с восстановлением после закрытия и конкурентного запуска worker/
receiver с удержанием первой отправки и подсчётом вызовов notify.
Локальный отчёт: `.test-tools/runs/20261002-115959-593df358/summary.json`.
Повторный инструментальный прогон прошёл на API 35: 5 тестов (миграции и ACK).
Отчёт: `.test-tools/runs/20261002-120059-970a0770/summary.json`.
Room-транзакция упорядочивает операции с базой, но отправка в NotificationManager
не откатывается вместе с ней при сбое процесса. Реальный жизненный цикл UI,
перезагрузка и доставка проверяются отдельно в R1.5. Быстрые ACK/edit/import и
гонки перепланирования остаются в шаге 2.

R1.4 реализован; полная локальная suite прошла: 51 тест. Пять новых сценариев
проверяют тихий повтор без ACK, паузу до повтора и её обновление, отсутствие
повтора после ACK, восстановление разрешения и новую пропущенную задачу во время
паузы. Локальный отчёт: `.test-tools/runs/20261002-123618-de4eb93c/summary.json`.
Повторный прогон миграций и ACK на API 35 прошёл: 5 тестов без ошибок.
Отчёт: `.test-tools/runs/20261002-123754-b1e221aa/summary.json`.
Открытый UI и запрет уведомлений откладывают отправку без обновления времени.
Перевод часов назад разрешает один повтор с новой отметкой времени; периодический
WorkManager не гарантирует доставку ровно через 15 минут. Реальные звук, канал,
запуски после перезагрузки и API 33 остаются в R1.5.

### Шаг 2. Последовательность фоновых операций

- [ ] R2.1: заменить создаваемые на каждую операцию executors на управляемые очереди.
- [ ] R2.2: сериализовать перепланирование из UI, репозитория, receiver и boot.
- [ ] R2.3: проверить быстрые edit/ACK/delete/import и завершение goAsync.

Готово, когда устаревший результат не заменяет актуальный будильник,
нет накопления потоков, а ошибки фоновых операций диагностируются.

### После стабильного релиза

- Swipe-to-acknowledge с защитой от случайного подтверждения.
- История событий задач и безопасная миграция для неё.
- Multi-select, массовые ACK/delete.
- Статистика и рекомендации после появления истории.
- Kotlin/Compose: небольшой пилот с сохранением текущей логики и данных.

Не возвращаем удалённые v1-классы в runtime. Офлайн-работа, отсутствие аккаунтов,
рекламы и сервера, расчёт следующего срока от фактического ACK остаются правилами продукта.
